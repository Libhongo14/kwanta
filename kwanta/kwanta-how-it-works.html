Why a view can't be faked

Two ways to verify a reward

The browser saying “I watched it” isn't enough on its own. How strong the proof is depends on which network path you run.

FREE · WIRED · DEFAULT

AdSense H5 Games Ads (web)

The ad's adViewed callback fires in the browser, then the page calls POST /api/ads/claim. There's no cryptographic server verification on web — so the server leans on other guards:

  • The claim must carry a single-use session token the server issued to that signed-in user, valid 15 minutes.
  • Bound by the daily ad cap, IP-velocity checks, and a unique-transaction guard (no double-credit).
  • Worst case abuse = a user farming their own capped account — not minting free points.
TRUE SSV · ALSO BUILT

AdMob rewarded (Android app)

The ad network's servers call POST /api/ads/ssv directly. The callback is signed, and the server verifies it against Google's public keys before crediting.

  • Signature checked with verifyAdmobSsv — a forged callback is rejected.
  • Reward is tied to the same single-use session via custom_data.
  • Genuinely un-fakeable. Use this when you wrap the game in an app.

Under the hood

The data model

Six tables. The balance is never a stored number you can tamper with — it's always the sum of the ledger.

users

  • email, password hash
  • phone + verified flag
  • status: active/flagged/banned

points_ledger

  • append-only entries
  • +earn / −redeem
  • balance = SUM(points)

ad_events

  • one row per verified view
  • unique transaction_id
  • revenue recorded

ad_sessions

  • single-use tokens
  • tie a view to a user
  • expire in 15 min

payouts

  • pending → approved → paid
  • points held on request
  • refunded if rejected

otp_codes

  • phone verification
  • expiry + attempt limit
Get it running

Run the app locally

You need Node.js 18 or newer (the build was made on Node 22). No database to install — SQLite is bundled.

Unzip and enter the folder

unzip kwanta.zip
cd kwanta

Install dependencies

Pulls in Express, better-sqlite3, bcrypt, and JWT.

npm install

If better-sqlite3 fails to build on Windows, install the “Desktop development with C++” workload (Visual Studio Build Tools). On macOS run xcode-select --install. On Linux you're usually fine.

Create your config

Copy the example and set your secrets. Leave ADSENSE_CLIENT blank for now — the app runs a simulated ad in dev so you can test the whole loop offline.

cp .env.example .env
# generate a strong secret:
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

Paste that value into JWT_SECRET (and generate another for AD_SSV_HMAC_SECRET). Add your own email to ADMIN_EMAILS so you can see the admin panel.

Initialise the database

npm run init-db

Start it

npm start

Open http://localhost:3000. Register an account, tap Watch ad & earn a few times, verify your phone (the dev code prints in the terminal), then request a payout.

See the admin side

Register (or sign in) with the email you put in ADMIN_EMAILS, then click Admin to review payouts and watch your revenue vs. margin update live.
