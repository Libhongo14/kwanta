Reward flow — the critical path

  1. Browser: user taps Watch ad & earn → POST /api/ads/session returns a single-use token (eligibility + caps checked).
  2. Ad plays. Web: browser confirms via adViewed → POST /api/ads/claim. App: ad network's server calls POST /api/ads/ssv with a signed payload.
  3. adReward verifies (signature for SSV / valid session for claim), rejects replays via the unique transaction id, and enforces the daily cap again.
  4. ledger appends +1. Balance recomputes as the sum. UI ticks up.
  5. At payout, points are held (a negative ledger entry) so they can't be double-spent; admin approves or rejects (refund).
